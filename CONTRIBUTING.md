# Contributing

Issues and pull requests are welcome. Small fixes with a test can go straight to a pull request. For a new feature or a larger change, it helps to open an issue first. That way we can check that it fits the project and agree on the scope before you write any code. If you have already built it, send the pull request and we'll see in the review whether it fits.

If a ZPL file imports incorrectly, paste the ZPL into the issue or attach it as a `.txt` file, and describe the expected result.

## Review

Every pull request is reviewed before merging. If there are suggestions, we work through them together. If you don't have time to follow up, a maintainer can take it from there.

## Pull requests

- Keep each pull request focused on a single issue or feature.
- Include tests where applicable. A bug fix needs a regression test that fails without the fix.
- Use `type(scope): description` for commit titles.

## AI

AI-assisted contributions are fine, provided you have reviewed and understood the code you submit. Please reply to review comments yourself.
